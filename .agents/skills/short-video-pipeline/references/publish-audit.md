# 发布前审核（Pre-Publish Audit）强制门禁

本文件与 [creatorhub-api.md](creatorhub-api.md) 解耦，专注发布前的媒体规格、文本洁净度、合规风控与各平台表单硬性校验，不依赖 CreatorHub 源码结构。

**强制门禁原则：无论是调用 CreatorHub 发布建任务接口（`POST /api/publish`），还是带定制封面交付用户手动发布，都必须先按本文件对每个目标平台逐项完成发布前审核。未通过硬性项的平台一律不得建任务或放行交付，防止表单报错、内容截断、视觉瑕疵或产生 `uncertain` 脏任务。**

---

## 一、通用发布前审核项（全平台必查，均为硬性拦截）

| 检查项 | 级别 | 校验标准 |
|---|---|---|
| **1. 媒体规格、安全区与声画完整度** | 硬性拦截 | 用 `ffprobe` 与 `qc_video.py audit-render` 核实成片文件存在、非空、1080×1920、视频流与音频流正常、真峰值 `≤ -1.0 dBTP`、时长与体积在平台限额内；核对 `output/check/qc-report.json` 零 `hard_failures`（**末尾 0.35s 无 `> -25 LUFS` 未落音截断人声、多段 BGM 无零淡化硬切、字幕无正序尾延延迟 Bug、末句无悬空半句、无元素定位于 `y≥1540px` 底部死区**）；且经 Agent 亲自打开 `output/check/safezone-grid.png` 与 `safezone-tail.png` 目检确认：顶 `≥180px`、底 `≥360px`、**右侧互动按钮禁区 `x=930..1080, y=850..1500` 无遮字/遮徽章**、全屏浮卡不挡嘴、卡片容器无 `overflow: hidden` 切底溢出。 |
| **2. 文本洁净度** | 硬性拦截 | 标题、正文、话题中不得残留占位符（如 `TODO`、`xxx`、`<标题>`、`{{...}}`）、Markdown 语法符号（`**`、`##`、`[]()`、`__`、反引号）、不可见控制字符（零宽空格、异常 `\r`/`\t` 等）、多余首尾空白或明显错别字。 |
| **3. 话题格式与拼接总长** | 硬性拦截 | 传给 API 的 `topics` 统一以英文逗号 `,` 分隔，每项不带 `#` 前缀、不含空格与非法符号、无重复标签；供人工复制的 `topics_display` 统一为 `#词1 #词2` 空格分隔单行；同时按实际发布形态核算「正文 + 拼接后的 `#话题`（含 `#` 与分隔空格）」总字符数，避免被平台或 CreatorHub 静默截断而腰斩末尾话题。 |
| **4. 合规与平台风控** | 硬性拦截 | 不得包含明显违禁词、极限/绝对化承诺用语（如「第一」「唯一」「100%有效」「绝对」「包过」）、站外硬导流信息（微信号、手机号、二维码引导、外部网址等，除非用户明确要求且自行承担风险）；核对无未证实数据或虚假宣称。 |
| **5. 账号与状态预检** | 硬性拦截（自动发布必查） | 走 CreatorHub 自动发布时，通过 `GET /api/accounts` 与 `GET /api/publish` / `GET /api/task-queue` 确认目标平台账号为 `active`、账号角色 **`account_role != "crawler"`**（须为 `publish` 或 `hybrid`，否则 CreatorHub `v0.4.0` 会直接返回 400 物理拦截）、未处于写暂停或风控冷却期，且该平台无未核对的 `uncertain` 任务阻断。带定制封面改走手动发布交付时不因登录态阻断交付，但发现异常应在汇报中提醒。 |
| **6. 文案规范、去秒数与品牌一致性** | 硬性拦截 | 核对已按 [copywriting.md](copywriting.md) 完整产出三平台四项文案（`cover_title`、`short_title`、`desc`、三层标签候选 `tag_candidates` + `topics_display`）并正确映射到各平台 `title`/`desc`/`topics`；封面承诺在成片内容中有明确呼应；**严禁在视频描述（`desc`）中提及任何具体秒数、时间点或片长数字**（核查不得出现「第XX秒」「XX秒起」「最后XX秒」「1分35秒」「00:36」「这支48秒短片」等数字+秒/分秒/时间戳表述，一律改用自然内容环节指代）；属于辰奕系列账号且用户未显式豁免时，核对 `desc` 中完整出现一次原句 **「用AI重构经营，让企业持续增长」** 且标签合理融入品牌词。 |
| **7. 封面规格与视觉门禁（生成定制封面时必查）** | 硬性拦截 | **① 基础通用硬校验（所有定制封面必查）**：核对对应封面目录（单片 `runs/<目录>/covers/`，入口 E 为 `master/covers/` 与 `variants/vN-<风格>/covers/`）下目标平台 PNG 存在、非空且分辨率精确匹配（抖音 `1080×1920`、视频号 `1080×1920`、小红书 `1080×1440`），主标题无溢出截断、主体清晰无遮脸/毛边/硬底边/错字/水印、抖音 3:4 裁切风险已核查，且经 Agent 亲自看图确认并写入 `cover-spec.json`（无看图能力时严禁伪造通过，须标 `pending_human_visual_review` 并停在 `waiting_approval` 交用户目检）；**② 系列专属校验（命中对应系列时叠加）**：命中「意图电商」系列规范（[cover-design.md](cover-design.md)）的封面须额外核对 `字号 × 字数 ≤ 980px`（`AI` 按 1.25 计、标点按 1 计）及第 12 节全部 8 项检查通过；非「意图电商」自定义封面不强套金色系列图与铜色平面条款。 |

快速媒体与声画/安全区/文案一体化自检命令（先执行 `env.sh`）：

```bash
python3 "$SVP_ROOT/.agents/skills/short-video-pipeline/scripts/qc_video.py" audit-render \
  --video "<成片路径>" --film-dir "<film目录>" --publish-json "<publish.json路径>" --out-dir "<output/check目录>"
```

## 二、分平台校验规则（补齐 CreatorHub 未前置拦截的表单坑）

每项规则均标明 **硬性拦截**（不通过必修正或阻断，禁止建任务）或 **建议项**（尽量满足，不单独阻断）。

### 1. 微信视频号（`shipinhao`）

| 检查项 | 级别 | 规则说明 |
|---|---|---|
| **短标题来源与长度** | **硬性拦截** | `title` 必须对应 [copywriting.md](copywriting.md) 的**短标题**（不要把两行封面标题直接塞进短标题框），严格控制在 **6–16 个汉字/字符**（不足 6 字或超过 16 字均可能被平台拒绝或截断报错）。 |
| **短标题符号白名单（含去空格）** | **硬性拦截** | **严禁包含**：逗号（`,`/`，`）、句号（`.`/`。`）、感叹号（`!`/`！`）、顿号（`、`）、破折号（`—`/`-`）、各类括号（`()`/`（）`/`[]`/`【】`）、斜杠（`/`/`\`）、竖线（`|`）、**空格（含中英文间空格）**、换行符及 Emoji 等特殊符号。平台仅允许极少数标点（`《》`、`""`、`:`、`+`、`?`、`%`、`℃`），**默认优先使用纯中文/字母/数字表达**（如将 `AI 对跨境电商的两层影响` 清理为 `AI对跨境电商的两层影响`），尽量避免一切非白名单符号。 |
| **正文 + 话题总长** | **硬性拦截** | 正文与拼接后的 `#话题` 合计 **≤ 1000 字**，不留截断残句。 |
| **位置 `location`** | 建议项（可选） | 不超过 **60 字**；视频号 POI 下拉匹配为实验性能力，匹配失败可能自动跳过，不作为发布成败依赖。 |

### 2. 小红书（`xhs`）

| 检查项 | 级别 | 规则说明 |
|---|---|---|
| **账号创作者权限** | **硬性拦截** | 走 CreatorHub 自动发布时，目标账号必须具备创作者登录（`has_creator=true`），否则接口或发布页必拒。 |
| **标题来源与规范** | **硬性拦截**（上限）/ **建议项**（保守长度） | 按 [copywriting.md](copywriting.md) 映射：`title` 优先采用**单行化封面标题（≤ 18 字且无冲突符号时）**，超限或含冲突符号时回退**短标题**。**硬性**：≤ **20 字**，不得包含 `#`、换行符及站外导流词；**建议**：因 Emoji/特殊符号在前端可能按双字节或加权计数，保守控制在 **≤ 18 字**。 |
| **正文 + 话题总长** | **硬性拦截** | 正文与拼接后的 `#话题` 合计 **≤ 1000 字**，正文必须为话题预留足够字符空间，严禁末尾话题被截断。 |
| **媒体规格** | **硬性拦截** | 视频发布仅限 **1 个文件**且文件大小 **≤ 1 GiB**。 |
| **话题数量** | 建议项 | 控制在 **3–8 个**高相关标签（含品牌词时一并计入），单标签简短无标点。 |

### 3. 抖音（`douyin`）

| 检查项 | 级别 | 规则说明 |
|---|---|---|
| **标题来源与规范** | **硬性拦截** | 按 [copywriting.md](copywriting.md) 映射：`title` 优先采用**单行化封面标题（≤ 30 字）**，超限时回退**短标题**。**硬性**：**≤ 30 字**，不得含换行符、控制字符或堆砌无意义特殊符号。 |
| **正文 + 话题总长** | **硬性拦截**（上限）/ **建议项**（精简长度） | **硬性**：正文与拼接后的 `#话题` 合计 **≤ 2000 字**；**建议**：短视频正文精简在 **300–500 字**内。 |
| **话题数量与格式** | **硬性拦截**（上限与格式）/ **强建议**（下限） | **硬性**：≤ **5 个**（超过 5 个易被平台截断或触发校验失败），API 侧无 `#` 前缀与空格；**强建议**：控制在 **3–5 个**（含辰奕品牌词时可取 `#辰奕` 与 `#用AI重构经营`，把余位留给行业与核心主题词）。 |
| **可见性与保存权限** | **硬性拦截（显式确认）** | 自动发布建任务前显式确认 `visibility`（默认 `public`）与 `allow_save`（默认 `true`）符合用户意图。 |

## 三、审核执行机制（放行、自动修正与阻断）

### 1. 逐平台输出审核清单并落盘
调用 `POST /api/publish` 或交付手动发布前，必须对每个目标平台逐项检查，并将结果写入 `runs/<目录>/publish/publish.json` 的 `audit` 字段：

```json
{
  "audit": {
    "checked_at": "2026-11-23T21:20:00+08:00",
    "passed": true,
    "common": {
      "media": { "passed": true, "codec": "h264+aac", "duration_sec": 28.5, "size_bytes": 12345678 },
      "copywriting": { "passed": true, "brand_slogan_checked": true, "note": "" },
      "covers": { "enabled": true, "passed": true, "spec_path": "runs/<目录>/covers/cover-spec.json" },
      "compliance": { "passed": true, "note": "" }
    },
    "platforms": {
      "shipinhao": {
        "passed": true,
        "checks": [
          { "item": "短标题长度(6-16)与符号/无空格白名单", "level": "hard", "passed": true },
          { "item": "正文+话题总长(<=1000)与四项文案齐全", "level": "hard", "passed": true },
          { "item": "封面尺寸(1080x1920)与视觉8项自检", "level": "hard", "passed": true },
          { "item": "账号状态/角色(!=crawler)/无uncertain阻断", "level": "hard", "passed": true }
        ],
        "auto_fixes": [
          {
            "field": "title",
            "reason": "视频号短标题含中英文空格",
            "before": "AI 对跨境电商的两层影响",
            "after": "AI对跨境电商的两层影响"
          }
        ],
        "blocked_reasons": []
      }
    }
  }
}
```

### 2. 可自动修正的格式问题（修正后必须复审）
属于纯格式/长度/符号问题，且能在**不改变原意**的前提下无损修正时，由 Agent 自动重写修正：
- 视频号短标题含中英文空格或禁用符号（如逗号、感叹号、Emoji）、超过 16 字或不足 6 字；
- 小红书封面标题超过 18/20 字需回退短标题、抖音标题超 30 字或含换行；
- API 侧 `topics` 带 `#` 前缀、含空格/中文逗号分隔、有重复项或抖音话题超过 5 个；
- 正文残留 Markdown 符号、多余首尾空白，或「正文 + 话题」总长超限；
- 视频描述（`desc`）误含具体秒数、时间点或片长表述（如「第24秒起」「最后30秒」「这条48秒短片」「1分35秒」），无损改写为自然内容节点指代（如「后半段」「片尾」「这条短片」）。

**修正后必须重新跑一遍完整审核**，确认所有硬性项全部通过后才允许调用 `POST /api/publish` 或放行交付，并在 `publish.json` 的 `audit.platforms.<平台>.auto_fixes` 中保留修正前后的 `before` / `after` 差异。

### 3. 不可自动修正的阻断项（禁止带病强行提交或交付）
出现以下任一情况，**必须立即阻断该平台发布/交付**，不得调用 `POST /api/publish`：
- 视频文件损坏、缺视频流或音轨、编码异常、体积超目标平台限额；
- 走自动发布时，账号登录失效、账号角色为仅采集号（`account_role=crawler`）、无创作者权限（小红书 `has_creator=false`）、处于写暂停/风控冷却，或该平台存在未人工核对的 `uncertain` 任务；
- 本次任务要求做定制封面但封面缺失、像素尺寸不符、标题行宽超限或视觉检查未通过；
- 内容触及明显违禁词、站外硬导流、极限绝对化承诺或未证实数据等合规红线，或封面承诺与成片严重脱节；
- 用户明确指定了固定文案，但与平台硬限制冲突且无法无损改写。

阻断时向用户清晰报告**具体失败项与修改建议**；若本次同时发多个平台，其余已通过审核的平台可按既定流程继续执行（如用户要求“一票否决/全停”则整单停下）。

## 四、实测踩坑补充（动态沉淀区）

**强制沉淀约定**：后续任何 Agent 在实测发布中遇到本文件尚未覆盖的新平台表单校验报错（如新增禁用符号、封面比例/清晰度限制、时长上下限、话题数量/敏感词新规、提交按钮灰置原因等），**必须在当次排查结束后把报错现象与规避规则按下方格式追加到本节**，让后续运行直接避坑。

记录格式：`- [YYYY-MM-DD][平台] 现象：... → 根因：... → 规避规则：...`

- `[2026-11-21][shipinhao]` 现象：短标题含中文逗号（如 `企业深度陪跑，现场解决问题`）存在触发视频号短标题标点校验失败或提交流程卡住/落入 `uncertain` 的风险 → 根因：视频号短标题输入框对标点符号采用严格白名单，且 CreatorHub 不会前置拦截禁用标点 → 规避规则：短标题严格控制 6–16 字，默认只用纯中文/字母/数字，禁止逗号、句号、感叹号、空格与 Emoji。
- `[2026-11-25][all/入口E]` 现象：实片反馈 `01-v1` 子片观感「像没结尾、戛然而止」，其余 3 片正常 → 根因：为强求切片机械零重叠，将 `v1` 尾点硬切在 `48.6s` 的转折半句「但是这个意图电商——」上，且无独立收尾镜头与尾韵停留 → 规避规则：所有成片及入口 E 子片在 `master-plan.json` 阶段即须锁定完整语义末句（`ending_sentence`）与收尾落版（`outro_design`），严禁截断在转折/引子半句上（允许相邻子片为完片收束保留极短结论句重叠），末句后留 `0.4–1.0s` 尾韵与 BGM 淡出，并纳入出片与发布前硬门禁。
- `[2026-11-25][all]` 现象：实片文案交付反馈整体认可，但三平台视频描述中频繁出现「第24秒起」「1分35秒起」「最后30秒」「这条48秒短片」等秒数与时长表述 → 根因：文案规则写「结尾指向一个值得看完或重看的具体位置」，执行时被机械化为时间戳秒数，既生硬又在微调剪辑后易穿帮 → 规避规则：视频描述严禁出现具体秒数、时间点或片长数字，统一改用内容环节指代（如「片尾的三格对照」「后半段的自查清单」），并纳入审核自动修正与硬拦截项。
- `[2026-11-25][all]` 现象：4 片实审发现全部 4 支成片下半屏卡片均侵入右侧互动按钮区（`x=930..1080, y=850..1500`），`00-master`/`02-v2` 全屏浮卡压住嘴部下巴、`03-v3` 3 张底卡掉进底部 360px 死区（`top: 1546..1554px`）、`02-v2` `s04` 评分卡溢底被 `overflow: hidden` 截断，且原 `check.json` 均误报通过 → 根因：仅靠裸画布小拼图目检，缺失右侧安全区规范与红框叠图校验 → 规避规则：强制执行四向安全区（右界 `x≤920px`、底界 `y≤1560px`、全屏下巴 `y≤1120px`），出片必跑 `qc_video.py audit-render` 并亲自目检 `safezone-grid.png` / `safezone-tail.png`。

## 五、母素材 + 母片 + 多子片矩阵附加审核门禁（入口 E 必查）

当本次运行走 **入口 E（[multi-variant.md](multi-variant.md)：「母素材确立 → 1 完整特效母片 + 3 延伸风格子片」）** 时，**除母片与 3 条子片各自独立完成前文全部通用 7 项及目标平台表单硬校验（写入各自 `publish/publish.json`）外，主 Agent 必须在最终放行 `delivery/` 交付包前逐项通过以下 6 项跨片矩阵硬门禁**（默认全三平台 `M=3`；若用户指定部分平台，则按 `run.json` 的 `target_platforms` 实际数量 `M` 校验；若 `covers_enabled: false` 则跳过第 4 项）：

| 检查项 | 级别 | 校验标准 |
|---|---|---|
| **1. 母素材确立、音频分轨与预处理签收** | 硬性拦截 | 核对 `master-assets/manifest.json` 完整存在且切片非空；未处理输入须满足 `run.json` 中 `gates.rough_cut_approved == true`（已处理输入为 `"skipped_processed"`），且 `rough-cut/preprocess.json` 中用户指定的全部追加预处理（如打马赛克时段/坐标、删改/合并）均已完成并核验无漏帧（无看图能力须经用户人工确认）；若经过删改/合并，核对逐字稿时间轴已与最终切片重算对齐；若原片自带 BGM，核对干净人声分轨 `vocals_track` 已就绪且各成片无双 BGM 叠音。 |
| **2. 4 条成片风格实质差异、安全区与声画闭环** | 硬性拦截 | 核对 1 母片 + 3 延伸子片在开头钩子结构、剪辑节奏/切镜频率、字幕与花字样式、主辅画面/特效包装及 BGM 情绪上确有实质差异，严禁仅换标题或微调顺序的伪多风格成片；同时逐片核对全部 4 份 `output/check/qc-report.json` 零 `hard_failures`，并由主 Agent 亲自打开 4 组 `safezone-grid.png` / `safezone-tail.png` 目检确认：**首句无残句废语、末句语义完整（对照 `master-plan.json` 的 `opening_hook`/`ending_sentence`/`outro_design`）、末尾 0.35s 无截断人声、最后核心卡停留可读 ≥ 1.5s、四向安全区（含右侧 `x=930..1080, y=850..1500` 与底 `y≤1560`）与全屏不挡嘴全部达标**。 |
| **3. 各片独立补素材合规** | 硬性拦截 | 核对母片及 3 条子片均按自身实际缺口独立补充了契合素材，4 份 `film/assets/credits.json` 全部完整、无媒体水印、无版权侵权、无 4 片照搬同一批补充 B-roll 的现象。 |
| **4. 全部目标平台封面规格与防撞帧（启用封面时必查）** | 硬性拦截 | 核对全部 `4 × M` 张（默认 12 张）目标平台封面 PNG 存在、尺寸精确（抖音 `1080×1920`、视频号 `1080×1920`、小红书 `1080×1440`）且经主 Agent 亲自看图通过各自 `cover-spec.json` 视觉自检（命中「意图电商」系列叠加第 12 节 8 项校验，非该系列按通用视觉硬校验，不得混套「意图电商」标题图；无看图能力时标 `pending_human_visual_review` 不得标通过）；同片内各平台不撞截帧、跨 4 片风格/主标题不撞车。 |
| **5. 全部目标平台文案跨片防雷同与去秒数** | 硬性拦截 | 核对母片与 3 条子片共 `4 × M` 套（默认 12 套）文案（4 份 `publish.json`）的封面标题、短标题、正文首句与精准主标签彼此清晰区隔，紧贴各自成片实际首句与落点；**全部 `4 × M` 条视频描述均不得提及任何具体秒数、时间点或片长数字**；若 `target_platforms` 含视频号则 4 套短标题均满足 6–16 字且无空格/禁用标点；若含抖音则 4 套话题均满足硬上限 ≤ 5 个（建议 3–5 个）。 |
