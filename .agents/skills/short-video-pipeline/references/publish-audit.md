# 发布前审核（Pre-Publish Audit）强制门禁

本文件与 [creatorhub-api.md](creatorhub-api.md) 解耦，专注发布前的媒体规格、文本洁净度、合规风控与各平台表单硬性校验，不依赖 CreatorHub 源码结构。

**强制门禁原则：在调用任何平台发布建任务接口（`POST /api/publish`）之前，必须按本文件对每个目标平台逐项完成发布前审核。未通过硬性项的平台一律不得建任务，防止表单报错、内容截断或产生 `uncertain` 脏任务。**

---

## 一、通用发布前审核项（全平台必查，均为硬性拦截）

| 检查项 | 级别 | 校验标准 |
|---|---|---|
| **1. 媒体规格** | 硬性拦截 | 用 `ffprobe` 核实成片文件存在、非空、视频流与音频流均正常、封装/编码为常见兼容格式（如 H.264 + AAC MP4）、无损坏；核实分辨率、时长与文件体积在目标平台限额内。 |
| **2. 文本洁净度** | 硬性拦截 | 标题、正文、话题中不得残留占位符（如 `TODO`、`xxx`、`<标题>`、`{{...}}`）、Markdown 语法符号（`**`、`##`、`[]()`、`__`、反引号）、不可见控制字符（零宽空格、异常 `\r`/`\t` 等）、多余首尾空白或明显错别字。 |
| **3. 话题格式与拼接总长** | 硬性拦截 | `topics` 统一以英文逗号 `,` 分隔，每项不带 `#` 前缀、不含空格与非法符号、无重复标签；同时按实际发布形态核算「正文 + 拼接后的 `#话题`（含 `#` 与分隔空格）」总字符数，避免被平台或 CreatorHub 静默截断而腰斩末尾话题。 |
| **4. 合规与平台风控** | 硬性拦截 | 不得包含明显违禁词、极限/绝对化承诺用语（如「第一」「唯一」「100%有效」「绝对」「包过」）、站外硬导流信息（微信号、手机号、二维码引导、外部网址等，除非用户明确要求且自行承担风险）；核对无未证实数据或虚假宣称。 |
| **5. 账号与状态预检** | 硬性拦截 | 通过 `GET /api/accounts` 与 `GET /api/publish` / `GET /api/task-queue` 确认目标平台账号为 `active`、未处于写暂停或风控冷却期，且该平台无未核对的 `uncertain` 任务阻断。 |

快速媒体自检命令（示例）：

```bash
ffprobe -v error -show_entries format=duration,size,format_name -show_entries stream=codec_type,codec_name,width,height -of json "<成片路径>"
```

## 二、分平台校验规则（补齐 CreatorHub 未前置拦截的表单坑）

每项规则均标明 **硬性拦截**（不通过必修正或阻断，禁止建任务）或 **建议项**（尽量满足，不单独阻断）。

### 1. 微信视频号（`shipinhao`）

| 检查项 | 级别 | 规则说明 |
|---|---|---|
| **短标题长度** | **硬性拦截** | 严格控制在 **6–16 个汉字/字符**（不足 6 字或超过 16 字均可能被平台拒绝或截断报错）。 |
| **短标题符号白名单** | **硬性拦截** | **严禁包含**：逗号（`,`/`，`）、句号（`.`/`。`）、感叹号（`!`/`！`）、顿号（`、`）、破折号（`—`/`-`）、各类括号（`()`/`（）`/`[]`/`【】`）、斜杠（`/`/`\`）、竖线（`|`）、空格、换行符及 Emoji 等特殊符号。平台仅允许极少数标点（`《》`、`""`、`:`、`+`、`?`、`%`、`℃`），**默认优先使用纯中文/字母/数字表达**，尽量避免一切非白名单符号。 |
| **正文 + 话题总长** | **硬性拦截** | 正文与拼接后的 `#话题` 合计 **≤ 1000 字**，不留截断残句。 |
| **位置 `location`** | 建议项（可选） | 不超过 **60 字**；视频号 POI 下拉匹配为实验性能力，匹配失败可能自动跳过，不作为发布成败依赖。 |

### 2. 小红书（`xhs`）

| 检查项 | 级别 | 规则说明 |
|---|---|---|
| **账号创作者权限** | **硬性拦截** | 目标账号必须具备创作者登录（`has_creator=true`），否则接口或发布页必拒。 |
| **标题规范** | **硬性拦截**（上限）/ **建议项**（保守长度） | **硬性**：≤ **20 字**，不得包含 `#`、换行符及站外导流词；**建议**：因 Emoji/特殊符号在前端可能按双字节或加权计数，保守控制在 **≤ 18 字**。 |
| **正文 + 话题总长** | **硬性拦截** | 正文与拼接后的 `#话题` 合计 **≤ 1000 字**，正文必须为话题预留足够字符空间，严禁末尾话题被截断。 |
| **媒体规格** | **硬性拦截** | 视频发布仅限 **1 个文件**且文件大小 **≤ 1 GiB**。 |
| **话题数量** | 建议项 | 控制在 **3–8 个**高相关标签，单标签简短无标点。 |

### 3. 抖音（`douyin`）

| 检查项 | 级别 | 规则说明 |
|---|---|---|
| **标题规范** | **硬性拦截** | **≤ 30 字**，不得含换行符、控制字符或堆砌无意义特殊符号。 |
| **正文 + 话题总长** | **硬性拦截**（上限）/ **建议项**（精简长度） | **硬性**：正文与拼接后的 `#话题` 合计 **≤ 2000 字**；**建议**：短视频正文精简在 **300–500 字**内。 |
| **话题数量与格式** | **硬性拦截 / 强建议** | 控制在 **3–5 个**（过多易被平台截断或触发校验失败），无 `#` 前缀与空格。 |
| **可见性与保存权限** | **硬性拦截（显式确认）** | 建任务前显式确认 `visibility`（默认 `public`）与 `allow_save`（默认 `true`）符合用户意图。 |

## 三、审核执行机制（放行、自动修正与阻断）

### 1. 逐平台输出审核清单并落盘
调用 `POST /api/publish` 前，必须对每个目标平台逐项检查，并将结果写入 `runs/<目录>/publish/publish.json` 的 `audit` 字段：

```json
{
  "audit": {
    "checked_at": "2026-11-22T22:30:00+08:00",
    "passed": true,
    "common": {
      "media": { "passed": true, "codec": "h264+aac", "duration_sec": 28.5, "size_bytes": 12345678 },
      "compliance": { "passed": true, "note": "" }
    },
    "platforms": {
      "shipinhao": {
        "passed": true,
        "checks": [
          { "item": "短标题长度(6-16)与符号白名单", "level": "hard", "passed": true },
          { "item": "正文+话题总长(<=1000)", "level": "hard", "passed": true },
          { "item": "账号状态与无uncertain阻断", "level": "hard", "passed": true }
        ],
        "auto_fixes": [
          {
            "field": "title",
            "reason": "视频号短标题含禁用逗号",
            "before": "企业深度陪跑，现场解决问题",
            "after": "企业深度陪跑现场解决真问题"
          }
        ],
        "blocked_reasons": []
      }
    }
  }
}
```

### 2. 可自动修正的格式问题（修正后必须复审）
属于纯格式/长度/符号问题，且能在**不改变原意**的前提下无损修正时，由 Agent 自动重写修正：
- 视频号短标题含禁用符号（如逗号、感叹号、空格、Emoji）、超过 16 字或不足 6 字；
- 小红书标题超 20 字（或含 Emoji 接近上限）、抖音标题超 30 字或含换行；
- 话题带 `#` 前缀、含空格/中文逗号分隔、有重复项或抖音话题超过 5 个；
- 正文残留 Markdown 符号、多余首尾空白，或「正文 + 话题」总长超限。

**修正后必须重新跑一遍完整审核**，确认所有硬性项全部通过后才允许调用 `POST /api/publish`，并在 `publish.json` 的 `audit.platforms.<平台>.auto_fixes` 中保留修正前后的 `before` / `after` 差异。

### 3. 不可自动修正的阻断项（禁止带病强行提交）
出现以下任一情况，**必须立即阻断该平台发布**，不得调用 `POST /api/publish`：
- 视频文件损坏、缺视频流或音轨、编码异常、体积超目标平台限额；
- 账号登录失效、无创作者权限（小红书 `has_creator=false`）、处于写暂停/风控冷却，或该平台存在未人工核对的 `uncertain` 任务；
- 内容触及明显违禁词、站外硬导流、极限绝对化承诺或未证实数据等合规红线；
- 用户明确指定了固定文案，但与平台硬限制冲突且无法无损改写。

阻断时向用户清晰报告**具体失败项与修改建议**；若本次同时发多个平台，其余已通过审核的平台可按既定流程继续执行（如用户要求“一票否决/全停”则整单停下）。

## 四、实测踩坑补充（动态沉淀区）

**强制沉淀约定**：后续任何 Agent 在实测发布中遇到本文件尚未覆盖的新平台表单校验报错（如新增禁用符号、封面比例/清晰度限制、时长上下限、话题数量/敏感词新规、提交按钮灰置原因等），**必须在当次排查结束后把报错现象与规避规则按下方格式追加到本节**，让后续运行直接避坑。

记录格式：`- [YYYY-MM-DD][平台] 现象：... → 根因：... → 规避规则：...`

- `[2026-11-21][shipinhao]` 现象：短标题含中文逗号（如 `企业深度陪跑，现场解决问题`）存在触发视频号短标题标点校验失败或提交流程卡住/落入 `uncertain` 的风险 → 根因：视频号短标题输入框对标点符号采用严格白名单，且 CreatorHub 不会前置拦截禁用标点 → 规避规则：短标题严格控制 6–16 字，默认只用纯中文/字母/数字，禁止逗号、句号、感叹号、空格与 Emoji。
